# InsightED PM App

Internal project-management app for about 7 people across about 15 subprojects. Read `docs/CONVENTIONS.md` and `docs/PROGRESS.md` before changing anything. Build plan: `docs/build_plan/`.

## Run it locally

1. `npm ci`
2. Create a local PostgreSQL 16+ database and put its connection string in a git-ignored `.env` (see `.env.example` for the shape). Needed: `DATABASE_URL`, `SESSION_SECRET`, `TZ`, `SEED_PM_PASSWORD`, `SEED_MEMBER_PASSWORD`. Optional: `PORT` (4000), `APP_TIMEZONE` (Asia/Manila), `SEED_MEMBER_COUNT` (6), `DB_POOL_MAX` (10).
3. `npm run db:migrate -w @myapp/backend` applies every migration from zero.
4. `npm run db:seed -w @myapp/backend` loads demo data (refuses to run in production or on a non-empty database).
5. `npm run dev` starts the API (:4000) and the web app (:5173) together. To run one alone: `npm run dev -w @myapp/backend` or `npm run dev -w @myapp/frontend`.
6. `npm run ci` runs lint, format check, typecheck, build and tests (tests use the `DATABASE_URL` database but only touch rows they create themselves).

## Migrations

Generated by drizzle-kit from `apps/backend/src/db/schema.ts`, plus hand-written SQL where Drizzle cannot express the rule. Never edit an earlier migration; add a new one.

| File                      | What it does                                                                                                                                                    |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `0000_functions.sql`      | Hand-written. `uuidv7()` fallback (only created on servers older than PostgreSQL 18, which has it built in) and the shared `set_updated_at()` trigger function. |
| `0001_core_tables.sql`    | Generated. Phase 1 enums, tables, indexes, CHECK constraints.                                                                                                   |
| `0002_core_integrity.sql` | Hand-written. Composite same-project foreign keys with column-list `ON DELETE SET NULL` (PG 15+) and the `updated_at` triggers.                                 |

## Dependencies worth a note

- `argon2`: password hashing (required by the stack).
- `cookie-parser`: reads the session cookie. `helmet`, `express-rate-limit`, `pino`, `pino-http`: security headers, rate limits, structured logs (stack).
- `tsup` (backend dev): bundles the API and the TypeScript-source `@myapp/shared` into one Node build.
- `concurrently` (root dev): runs the backend and frontend dev servers from a single `npm run dev`, with labelled output and one Ctrl+C to stop both.
- `jsdom` (frontend dev): gives the dev logger's unit test file (`src/devtools/dev-logger.test.ts`, via a per-file `@vitest-environment` comment) a browser-like `window`, `localStorage` and `fetch`; the other tests stay in Node.
- `tsx` (backend dev): runs TypeScript directly for `dev`, `db:migrate` and `db:seed`.
- `supertest` (backend dev): HTTP-level tests of the Express app.

## Notes

- PgBouncer: connection timeouts are sent as startup parameters, never session `SET`s. If PgBouncer rejects them, add `statement_timeout,idle_in_transaction_session_timeout,options` to its `ignore_startup_parameters`.
- CI runs PostgreSQL 16, so the `uuidv7()` fallback in `0000_functions.sql` is what CI exercises; local PostgreSQL 18 uses the built-in.

- Phase 3 tooling: `npm run db:seed:perf -w @myapp/backend` loads about 50,000 activities (local only); `npm run db:explain -w @myapp/backend` regenerates `docs/db-plans.md`. Remove perf rows with `PERF_RESET=1 PERF_COUNT=0`.

- Frontend: `npm run dev -w @myapp/backend` (API on :4000) and `npm run dev -w @myapp/frontend` (web on :5173, proxies `/api`). Sign in with a seeded user (`pm@insighted.local` or `member1@insighted.local`); passwords are the seed values in your `.env`.
- Dev diagnostics: `npm run dev` now starts the same two servers through `tools/dev-diagnostics/dev-runner.mjs` and writes browser errors, backend errors, slow requests and queries, and lint and type findings to the git-ignored `.logs/` folder; `.logs/LATEST.md` is the digest to read first (`npm run logs:summary` rebuilds it, `npm run logs:clear` empties it). `npm run dev:raw` is the original command with no logging. Everything is inert in production.
